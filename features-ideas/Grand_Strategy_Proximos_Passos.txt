

3. CRIAR O CONCEITO DE GAMESTATE
--------------------------------
PRIORIDADE: ALTA

Não reescrever o jogo inteiro.

Primeiro apenas definir o conceito:

interface GameState {
  date: GameDate;

  world: {
    provinces: Province[];
    countries: Country[];
  };

  military: {
    armies: Army[];
    wars: War[];
    activeBattles: ActiveBattle[];
    recruitments: Recruitment[];
  };

  diplomacy: {
    relations: DiplomaticRelation[];
  };

  economy: {
    constructions: BuildingConstruction[];
  };

  technology: {
    player: CountryTechState;
    bots: Map<string, CountryTechState>;
  };
}

No futuro:

economy:
  resources
  production
  market
  trade

society:
  population
  satisfaction
  unemployment

politics:
  parties
  government
  laws
  legitimacy

Não é necessário colocar tudo dentro dele agora.
O objetivo inicial é ter um mapa mental claro de onde cada dado pertence.

============================================================
FASE 2 — POPULAÇÃO
============================================================

7. POPULATION V1
----------------
O projeto já possui população e crescimento populacional em partes da lógica atual.
Portanto, evoluir o sistema existente em vez de criar outro paralelo.

Começar simples:

type ProvincePopulation = {
  total: number;
  growthRate: number;
  employed: number;
  unemployed: number;
  satisfaction: number;
};

Primeiras relações:

crescimento econômico
→ empregos
→ satisfação

guerra
→ mortes/perdas
→ menos trabalhadores
→ menor produção

impostos altos
→ menor poder de compra
→ menor satisfação

desemprego
→ maior insatisfação

------------------------------------------------------------

8. POPULAÇÃO + UNREST
---------------------
O sistema atual de unrest já é uma boa base.

Evolução:

satisfação da população
→ unrest
→ protestos
→ rebelião

Não criar um segundo sistema paralelo de insatisfação.

------------------------------------------------------------

9. POPULAÇÃO + ECONOMIA
-----------------------
Criar a cadeia:

população
→ trabalhadores
→ capacidade produtiva
→ bens
→ preços
→ poder de compra
→ satisfação
→ estabilidade

Isso começa a transformar o jogo em uma simulação social/econômica.

============================================================
FASE 3 — RECURSOS E PRODUÇÃO
============================================================

10. RECURSOS ESTRATÉGICOS
-------------------------
Começar com poucos recursos:

Food
Iron
Coal
Oil
Wood
RareMaterials

Algo entre 5 e 8 recursos é suficiente no início.

Cada província pode possuir:
- produção;
- capacidade;
- estoque.

------------------------------------------------------------

11. PRODUÇÃO
------------
Depois dos recursos, criar cadeias produtivas.

Exemplo:

Farm
→ Food

Iron Mine
→ Iron

Steel Mill
→ Iron → Steel

Military Factory
→ Steel + recursos → Equipment

Cadeia:

Iron
→ Steel
→ indústria militar
→ equipamentos
→ exército

============================================================
FASE 4 — MERCADO
============================================================

12. PREÇOS DINÂMICOS
--------------------
Começar com apenas:

price
supply
demand

Regra básica:

demanda > oferta
→ preço sobe

oferta > demanda
→ preço cai

Guerra:
→ consumo aumenta
→ estoque diminui
→ preço aumenta

Paz:
→ consumo diminui
→ estoque recupera
→ preço diminui

------------------------------------------------------------

13. INFLAÇÃO
------------
Depois dos preços:

price index
→ inflação

A inflação deve afetar:
- construção;
- salários;
- consumo;
- renda real;
- satisfação.

Não criar inflação apenas como número visual.

============================================================
FASE 5 — COMÉRCIO INTERNACIONAL
============================================================

14. TRADE
---------
Criar comércio entre países.

Exemplo:

País A:
+100 Iron

País B:
-50 Iron
+Food

Acordo:
A exporta Iron
B exporta Food

Depois adicionar:
- tarifas;
- bloqueios;
- embargo;
- rotas;
- dependência econômica.

------------------------------------------------------------

15. COMÉRCIO + DIPLOMACIA
-------------------------
O comércio deve alimentar a diplomacia.

Exemplo:

dependência de petróleo
→ necessidade de parceiro
→ relações melhores

embargo
→ falta de petróleo
→ produção cai
→ preços sobem
→ população sofre
→ governo reage

============================================================
FASE 6 — POLÍTICA INTERNA
============================================================

16. GRUPOS POLÍTICOS
--------------------
Começar com poucos grupos:

Trabalhadores
Industriais
Militares
Ruralistas
Comerciantes

Cada grupo possui interesses.

Não criar partidos extremamente complexos ainda.

------------------------------------------------------------

17. LEIS COMO TRADE-OFFS
------------------------
As leis atuais são uma excelente base.

Transformar:

"bonus"

em:

"benefício + custo"

Exemplo:

Imposto alto
→ + receita
→ - poder de compra
→ - satisfação

Recrutamento alto
→ + manpower
→ - trabalhadores
→ - produção
→ + custo social

Estado centralizado
→ + controle
→ - liberdade política

Isso torna as decisões realmente estratégicas.

============================================================
FASE 7 — EVENTOS E PERSONAGENS
============================================================

18. EVENTOS CONDICIONAIS
------------------------
Evitar eventos aleatórios sem contexto.

Preferir:

IF unemployment > 15%
AND satisfaction < 40
THEN protest event

Outro exemplo:

IF food shortage
AND war
THEN rationing event

O evento deve nascer das condições do mundo.

19. PERSONAGENS
--------------

- líderes;

- ministros;
- governadores;
- diplomatas.

Possíveis atributos:
- traits;
- age;
- loyalty;
- influence;
- skills.

Não implementar isso cedo demais.

FASE 9 — IA AVANÇADA
============================================================

21. NÃO TORNAR A IA COMPLEXA CEDO DEMAIS
----------------------------------------
A IA já possui economia, movimento, tecnologia e decisões militares.

Primeiro construir os sistemas do mundo.
Depois fazer a IA reagir a eles.

Arquitetura desejada:

IA
→ decide o que quer fazer

ENGINE
→ verifica se pode fazer

Exemplo:

IA:
"Quero invadir X."

Engine:
"Você não possui manpower."

IA:
"Então preciso aumentar recrutamento."

Outro:

IA:
"Quero atacar X."

Engine:
"Você depende do petróleo de X."

IA:
"Preciso garantir outra fonte."

------------------------------------------------------------

22. PERSONALIDADE DA IA
-----------------------
Depois criar perfis:

Militarista
Expansionista
Defensivo
Industrial
Comercial
Diplomático

A mesma situação pode gerar decisões diferentes.

Exemplo:

déficit de recursos:

AI comercial
→ acordo

AI militarista
→ conquista

AI defensiva
→ produção militar

AI diplomática
→ alianças

O QUE NÃO FAZER AGORA
============================================================

Não implementar agora:
- multiplayer;
- modding completo;
- personagens extremamente complexos;
- dezenas de recursos;
- IA extremamente sofisticada;
- sistema político gigantesco;
- refatoração total do GameState;
- otimizações prematuras.

Essas partes dependem de uma base mais madura.

============================================================
REGRA DE OURO
============================================================

Antes de adicionar uma funcionalidade, perguntar:

1. Qual problema do jogo ela resolve?
2. Com quais sistemas ela interage?
3. Qual consequência ela produz?
4. O jogador percebe essa consequência?
5. A IA pode reagir a ela?
6. Precisa ser salva?
7. Precisa entrar no GameState?
8. Precisa de teste?

Se ela apenas adiciona mais um número na tela, provavelmente ainda não é a hora.

============================================================
PRÓXIMO PASSO PRÁTICO
============================================================

O próximo trabalho recomendado é:

1. Abrir o sistema atual de save/load.
2. Criar os tipos do SaveGameV2.
3. Remover os any dessa parte.
4. Garantir serialização correta de Map e estruturas especiais.
5. Criar teste: salvar → carregar → comparar estado.
6. Criar o GameState conceitual.
7. Documentar a ordem dos ticks.
8. Só então começar Population V1.

Não começar Population antes de deixar o save/load minimamente preparado.

Motivo:
Population, Resources, Production, Market e Politics aumentarão muito a quantidade de
dados persistentes e tornarão o save/load cada vez mais sensível.
